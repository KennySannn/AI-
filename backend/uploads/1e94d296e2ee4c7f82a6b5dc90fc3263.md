## 阶段 1：聊清楚要做什么

把下面这段话发给 WorkBuddy：

```
我想做一个学习助手。
场景是这样的：我在学大模型课程，手里有很多 PDF、PPT、Markdown 资料，
看完就忘。我想有个工具，能帮我把资料上传上去，然后我跟它聊资料里的内容，
它能基于资料回答我。最好还能自动出题考我，帮我看看哪些知识点没掌握。
我设计的功能是：传资料、聊资料、做测评、看进度、出周报。记住我的所有要求，禁止发散。在我说开始开发之前，禁止开发。
```

## 阶段 2：把想法变成文档

```
根据我描述的5个功能，帮我整理出来下面这些内容，并形成功能需求文档：

1. 每个功能拆成小功能点，标一下哪些必须先做哪些可以后做
2. 需要哪些后台接口，列出来（什么地址、传什么参数、返回什么）
3. 数据库要存哪些东西，帮我设计一下表
4. 你是这个学习助手的AI大脑，我需要给你写"人设"，即三套系统提示词：
   - 日常聊天时，你是AI大模型的学习导师，说话有洞察不啰嗦，优先用资料内容回答
   - 出题时，你严格基于资料出题，出选择+判断+简答三种
   - 改卷时，你帮我对答案，选择题对就是对错就是错，简答题给0/0.5/1分
   帮我写成正式的指令。禁止发散。在我说开始开发之前，禁止开发。
```

- **会生成一个《功能需求文档.md》**
- 对功能需求文档进行审核

## 阶段 3：做界面

### 先搭个架子

- **把《claude.md》文件放入工作空间中**，WorkBuddy会自动找到该文件，并读取文件内容

```
好，现在进入我们的前端开发环节，先帮我做一个网页的框架，在工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行。

前端目录为frontend
技术就用纯 HTML/CSS/JS。
CSS 拆分几个文件：reset（变量+重置）、layout（布局）、components（组件）、pages（各页面）。
JS 拆分：app.js 管路由（用 # 锚点切换页面）、api.js 封装请求。
用 CSS 变量管颜色。

整个页面暗色背景，金色做点缀。
顶部放导航栏，5个Tab：学习、资料库、测评、进度、报告，点了能切换。
右边角上放一个小圆点，后台连上就亮绿色，断了就亮红色。
```

### 学习对话页

```
现在开始做"学习"这个页面，核心功能是跟AI聊天。在工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行：

- 顶部有个下拉框，能选我上传的资料，选哪份就跟哪份聊，如果没有选择就是默认普通对话，不引用资料。
- 下拉框旁边有个"新对话"按钮，是用来重置对话的。
- 中间是聊天区，用户输入的内容显示靠右白底黑字，AI回复的内容靠左
- 左侧是历史对话区，左侧宽度占比20%，所有对话上下文信息都需要存储，方便用户可以找到历史对话聊天
- AI的消息太长的话，标题、列表、代码块这些要排版好看
- AI回的消息下面有个小箭头，点开能看到它引用了资料的哪些段落
- 最下面是输入框，回车发送，shift+回车换行
- 发送的时候输入框禁用，显示"正在思考..."的动画
- 没发过消息的时候，中间显示一个图标加引导语
```

```

第一步 - 开始前：
```

### 先搭骨架

```
现在帮我做后端开发。用 Python 的 Flask  框架。工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行。

先把整个后台的骨架搭起来：该建的文件建好，配置文件写好，目录应该为backend。
不使用向量模型，不用RAG，查资料功能是直接根据选择的文档资料+LLM回答用户，大模型的访问URL和APIKEY应该能够单独配置。
数据库表建好（用我们在功能需求文档中设计的那些表）。
```

### 资料处理能力

- 这部分处理，时间较长

```
首先后端要能处理我上传的资料，工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行：

- PDF、PPT、Word、Markdown、TXT 都能读出来里面的文字
- 读出来的文字，都要存储到数据库，并和文档关联，方便后面针对文档进行检索
- 当用户上传一份资料就要自动走完整个流程：文件存储 → 读文字 → 存好
- 这个处理放到后台慢慢跑，用户不用等着
- 删资料的时候，文件、数据库记录一起删干净
```

### AI 大脑

```
后端要接入 DeepSeek 大模型。用功能需求文档中写的三份系统提示词。工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行

需要deepseek大模型实现下面几个能力：
- 聊天时：把我选的资料内容搜出来相关的段落，和我的问题一起发给 AI，让 AI 基于这些内容回答
- 出题时：把我选的资料内容给 AI，让它出题。题型配比大概是 1/4 判断 + 1/2 选择 + 剩下简答。
  难度也是简单中等较难搭配
- 改卷时：把题目和我的答案给 AI，让它批改打分
- 出周报时：把这周我学了什么、薄弱点是什么告诉 AI，让它写报告

如果网不好调用失败了，自动重试最多 3 次。
AI 有时候会在 JSON 外面包一层 ```json```，要自动去掉。
```

### 接口

```
接下来把我们之前设计的那些接口一个一个做出来，工作之前仔细阅读我们的功能需求文档和claude.md文件，严格按照要求执行。

资料相关的：上传、列表、详情、删除、重新解析
聊天相关的：创建对话、对话列表、发消息、历史消息、删对话等
测评相关的：开始测评（AI出题）、提交答案（AI改卷）、查看结果、历史记录
进度相关的：总览统计、知识点掌握度、薄弱点、周报生成、周报下载

注意：发消息那个接口最核心，流程是搜资料 → 拼上下文 → 调AI → 存消息 → 返回结果。
```

```

为前端frontend的服务启动，在项目根目录下编写一个可执行文件（windows系统生成start_frontend.bat文件，mac系统生成start_fronted.sh文件）

必须确保在windows系统可以正常启动，必须确保在Mac系统下能正常启动！
项目中的路径不可以使用绝对路径，必须确保能在windows和mac下都可以正常运行！
```
